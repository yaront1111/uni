# packages/api

`@unai/api` owns the Fastify HTTP boundary, the production route composition and the process entry point. It must not own schemas or DTO shapes (`@unai/domain`), queue SQL (`@unai/jobs`), session logic (`@unai/auth`) or anything registry-related. No workspace package imports it: `apps/web` reaches it only over verified TLS through `apiRequest` in `apps/web/lib/server.ts` (the `[...path].ts` proxy for POSTs, `getServerSideProps` for GETs).

## Surface

- `package.json` exports only `src/index.ts` (`createApiBoundary`, `ApiBoundaryOptions`). `createPlatformApi`, `createEvidenceObjects` and `importSource` are reached by relative import (`./platform.js`, `./evidence.js`) from `server.ts` and the tests.
- `createApiBoundary` installs no routes and no auth provider. Its `preParsing` hook refuses in a fixed order: socket not TLS (426 `TLS_REQUIRED`), `authenticate` (401 `AUTHENTICATION_REQUIRED`), `requestContextSchema` (400 `REQUEST_CONTEXT_INVALID`), `authorize` (403 `ACCESS_DENIED`), then the idempotency key on POST/PUT/PATCH/DELETE (400 `IDEMPOTENCY_KEY_REQUIRED`). `index.test.ts` asserts through its `seen` array that `authorize` is never called for a request refused earlier. The instance runs with `trustProxy:false`, so `x-forwarded-proto` never stands in for an encrypted socket (ADR 0008, first test in `index.test.ts`), and with a 1 MiB `bodyLimit` that must keep fitting the base64 envelope of the 512 KB documents `apps/web/components/Evidence.tsx` accepts.
- The boundary checks only the shape of `idempotency-key` (`[a-zA-Z0-9_-]{16,128}`); it stores nothing and deduplicates nothing. Device and ops routes ignore the value. Only evidence ingest uses it: the body's `idempotencyKey` must equal the header (400 `IDEMPOTENCY_KEY_MISMATCH`) and is bound to the item in `evidence_ingestion_receipts`.
- `createPlatformApi` adds a `preHandler` that maps `request.routeOptions.url` (the route pattern, not the raw URL) to the single purpose allowed there, else 403 `PURPOSE_REFUSED`. Only `/v1/devices` distinguishes GET from other methods; the correction routes in `CORRECTION_URLS` all map to `memory.correct` in both directions, because the write and the read of the overlay are the same surface. A purpose missing from the `purposes` set therefore fails earlier as `ACCESS_DENIED`; a known purpose on the wrong route fails as `PURPOSE_REFUSED`.
- `server.ts` has top-level await and side effects, so tests never import it. `packages/secrets/src/index.test.ts` scans its source text: database URLs must be read with `requireSecret(secrets,'NAME')`, never with `required('NAME')`.

## Invariants

- Every data route runs inside `deviceWork`, which `createPlatformApi` hands to `registerEvidenceRoutes` and `registerOpsRoutes` as `work`. It resolves the session again, requires `session.ownerScopeId` to equal the header scope, opens `withOwnerTransaction`, and takes `SELECT ... FOR UPDATE` on the live `auth_sessions` row. That lock serializes the requests of one session; device registration relies on it so that a retry returns the session's existing device (`docs/foundation.md`). `/v1/sessions/revoke-all` is the only route outside it and writes through `authPool` via `revokeSessions`.
- `unai_app` holds column-level grants on `auth_sessions` (`migrations/0002_authentication.sql`: SELECT without `token_hash`, UPDATE of `device_id` and `revoked_at` only), so `SELECT *` on it fails at runtime. Revoking a device ends its sessions through the `revoke_removed_device_sessions` trigger, not through code here.
- Returning `reply.code(4xx).send({code})` from inside `run` still commits the transaction; throwing rolls it back. A thrown `Error` never reaches the client, because `setErrorHandler` answers 500 `INTERNAL_ERROR`; `SESSION_EXPIRED` from `deviceWork` therefore surfaces as a 500 on device and ops routes, and on evidence routes too, because the failure audit in `scoped` calls `work` again and that second throw escapes.
- Every successful route inside `deviceWork` calls `tx.audit` with snake_case column names in `fields`; `/v1/sessions/revoke-all` is audited by the SQL function `unai_private.auth_revoke_session` instead. `auditEventSchema` caps `objects` at 100, hence `slice(0,100)` on list routes. Tests find the audit row by `correlation_id`.
- Rows leave through strict `@unai/domain` schemas (`publicDeviceSchema`, `publicEvidenceSchema`, `deadLetterViewSchema`, `retryResultSchema`; `listJobs` applies `jobsViewSchema` inside `@unai/jobs`), so a new response field is added there first. Only the small acknowledgements (`{removed:true}`, `{revoked:true}`, the `{evidenceId, ingestionStatus}` of an ingest) and the wrapper object of `/v1/connectors/:id` are built by hand. Tests search response bodies for `token|hash|key`, for `payload`, and for the stored `object_store_key` value.
- Error bodies are not uniform: boundary and evidence refusals send `{code, correlationId}`, while device, ops and `PURPOSE_REFUSED` replies send `{code}` only.

## Evidence routes (`evidence.ts`)

- `scoped` validates `x-data-purpose` and `x-maximum-sensitivity`, then sets `unai.data_purpose` and `unai.maximum_sensitivity` with transaction-local `set_config`. The RLS function `unai_private.evidence_access` reads both and hard-codes its purpose list; migrations 0011, 0012 and 0014 have each replaced it to add one, and it now admits `evidence.ingest`, `evidence.read`, `connector.read`, `memory.extract`, `memory.canonicalize`, `memory.govern` and `memory.correct`. Without the settings `source_items` yields no rows, and a new evidence purpose needs a new migration that replaces that function.
- `ingestOwnerStatement` is the correction path's way in (`corrections.ts`): it calls the same `ingest`, so an owner statement gets the same content hash, receipt, durable object and recorded triage route as any other item, and anchors it as one `MESSAGE_SPAN`. It is the reason `createEvidenceObjects` accepts `memory.correct` as a write purpose alongside `evidence.ingest` (`OBJECT_WRITE_PURPOSES`); widening that set widens who may write raw bytes, so add to it only with the matching migration.
- Inside `scoped`, refuse by throwing `Refusal(status, code)`. Anything else, including a Zod failure in `publicRow` or an RLS violation, becomes 503 `EVIDENCE_UNAVAILABLE`, so a 503 in a test is not necessarily a storage problem. After the rollback `scoped` writes the audit in a second `work` transaction: DENY/REFUSED below 500, ALLOW/FAILURE from 500 up.
- The order inside `ingest` is load-bearing: advisory lock on owner scope plus idempotency key, receipt conflict check, `INSERT ... ON CONFLICT DO NOTHING`, receipt binding, and only for a new row the `evidence_object_keys` insert before `objects.put`. The resolver in `createEvidenceObjects` reads that key back through the same transaction (bound with `AsyncLocalStorage`) to authorize the write, and answers null (`STORAGE_ACCESS_DENIED`) for any other context. The HTTP response drops `stored` on purpose so that a retry is indistinguishable from the first submission.
- `content_hash` covers `canonical(content)`: recursively sorted keys, array order kept. Changing `canonical` breaks deduplication against every stored row. Identity is the `source_items_identity` constraint (owner scope, connector, source type, external id, content hash): a duplicate keeps the first write's metadata, and changed content under a new key becomes a new row (ADR 0010).
- `importSource` has no route and no production caller; only `source-import.test.ts` calls it, with payloads from `fixtures/sources/`. The caller must pass an `evidence.ingest` owner transaction that already has both `unai.*` evidence settings, and owns error mapping and failure audit, which `scoped` does for the HTTP routes. The idempotency key is derived from the parsed identity, and anchor re-import relies on the `source_anchors_identity` index from migration `0008`. `Refusal` is not exported, so callers match on the error message.
- `evidence.ts` imports `../../storage/src/index.js` and `../../../src/kernel/identities.js` (`uuidV7`) by relative path; `@unai/storage` is not declared in `package.json`.

## Adding a route (local steps on top of the root checklist)

Put it in a `register*Routes(app, work)` module called from `createPlatformApi`. Validate params and body before calling `work` and answer a stable code. Keep SQL for another package's tables in that package: the ops routes contain none and call `@unai/jobs`, which re-checks the purpose with `requirePurpose`. Audit, parse the response through a domain schema, and add the refusal cases `ops.test.ts` has (wrong purpose, foreign owner scope, missing correlation id, missing idempotency key, unknown session). `registry-boundary.test.ts` fails on any route path matching `registr|contract|release` on any file path in this package containing "registr", and on any non-test `.ts`, `.tsx` or `.json` file here that mentions `@unai/registry`, `packages/registry` or `registry/releases`.

## Tests

- No database needed: `pnpm exec vitest run packages/api/src/index.test.ts packages/api/src/registry-boundary.test.ts packages/api/src/reference-stack.test.ts`, run from the repo root because paths resolve from the working directory; the TLS case needs OpenSSL. `reference-stack.test.ts` is a repo-wide guard that happens to live here: it scans every workspace manifest and the lockfile for graph, vector and redis packages, requires `fastify` in this manifest, and requires every file in `migrations/` to be tracked or at least not ignored by Git.
- The database tests (`platform`, `evidence`, `ops`, `source-import`) each create their own login role (`platform_test_app`, `ops_test_app`, ...) with `GRANT unai_app` and build `appPool` by swapping those credentials into `UNAI_TEST_DATABASE_URL`. The admin pool doubles as `authPool` but cannot be `appPool` (`DATABASE_ROLE_UNSAFE`). A new file follows the pattern with a new role name; files run in parallel on one database, so scope assertions by owner scope or correlation id.
- Tests fake TLS with an `onRequest` hook that defines `socket.encrypted`, call `app.inject`, and create users and sessions through `postgresAdapter(admin)`. `authorize` turns every exception into `false`, so a misconfigured pool shows up as 403 `ACCESS_DENIED` on every request rather than as a 500.
- Evidence tests use an in-memory `EvidenceObjects` double, except one real TLS/KMS case that requires `UNAI_TEST_S3_ENDPOINT`, `UNAI_TEST_S3_BUCKET` and `UNAI_TEST_S3_KMS_KEY_ID`.
