# src

`src/` owns the original in-memory memory-kernel slices (`kernel/`), the wrapper's work-item lease ledger (`wrapper/claims.ts`) and the repo-wide architecture guard `architecture.test.ts`. It must not own persistence, HTTP, SQL or Zod schemas, which live in `packages/`; the only imports in the non-test modules are `node:crypto` and sibling files. ADR 0001 requires these existing memory-kernel sources to be preserved, so do not delete them or fold them into a package.

## Public surface and consumers

- There is no barrel. `index.ts` exports only `UAI_KERNEL_VERSION` (pinned to `"0.1.0"` by `index.test.ts`); every module is imported by file path, and a new slice does not need to touch `index.ts`.
- `uuidV7()` in `kernel/identities.ts` is the one export with production consumers: `packages/api/src/evidence.ts`, `packages/jobs/src/index.ts` and `packages/registry/src/snapshot.ts` import it as `../../../src/kernel/identities.js` to mint primary keys for `uuid` columns. The two lanes are therefore connected at exactly this point. Its zero-argument signature and lowercase canonical UUIDv7 output are load-bearing (`packages/registry/src/snapshot.test.ts` asserts the format on stored ids).
- Everything else (`createEvidenceLedger`, `stampProvenance`, `redactSecrets`, `createClock`, the note store, `openClaimStore`/`bootWrapper`) has no consumer outside `src/`; apart from `provenance.ts` composing the clock and the redaction guard, each is exercised only by its own test file. The API's evidence route is a separate PostgreSQL/S3 implementation, not a wrapper around `kernel/evidence.ts`, and `SENSITIVITY_LEVELS` here is duplicated by `sensitivitySchema` in `packages/domain/src/evidence.ts`; a change to one side does not reach the other.

## Invariants a change must keep

- Identity is never a hash (PRD §13.1/13.2, §42 invariant 27). Every `mint*Id` takes no parameters, and `identities.test.ts` and `evidence.test.ts` assert `mint.length === 0` plus the UUIDv7 pattern. A new id kind is a `SurrogateId<"Brand">` alias with a zero-argument minter that casts `uuidV7()`; do not add a second generator (`note.ts` and `evidence.ts` both reuse it). `contentHashOf`, `slotKeyOf` and the dedupe tuple are lookup keys only.
- Every record handed out is frozen, and caller input is copied before it is stored (`deepFreeze`, an array spread and `structuredClone` in `evidence.ts`, the `seal*` helpers in `claims.ts` and `note.ts`). The tests assign to returned records expecting a `TypeError`, and empty the seed array given to `createMemoryBackend` expecting the store to be unaffected, so never keep a caller's reference. `evidence.test.ts` also asserts with `toBe` that reads and deduplicated repeats return the same stored object, so do not clone on read.
- `createEvidenceLedger().ingest` order is fixed: idempotency-key lookup, then the PRD §33.2 tuple `[ownerScopeId, connectorId, sourceType, externalId, contentHash]`, then a complete synchronous write to every map, and only then `extractionHook`. The hook runs for fresh records only, and a throwing, rejecting or never-settling hook must not change the result. A key that arrives with a deduplicated repeat binds to the existing record, and a replayed key with different content silently returns the bound record (the API lane refuses that case with `IDEMPOTENCY_CONFLICT`). A repeat never restates fields outside the tuple: the first write wins. Storage is partitioned by owner scope.
- `provenance.ts` is scanned as source text by `provenance.test.ts`: after block comments and whole-line `//` comments are stripped (a trailing comment on a code line still counts) the code may not contain `Date`, `toISOString`, `toJSON`, `Intl`, a date literal, `new RegExp`, a regex `.test(`/`.exec(`, `.replace(`/`.match(`/`.search(`/`.split(`, `REDACTED`, `API_KEY`, `bearer` or `sk-`, and the two imports must read exactly `from "./clock.ts"` and `from "./redaction.ts"` (double quotes). The stamp has exactly three keys.
- `redaction.ts` matches all three secret kinds (`ANTHROPIC_API_KEY=`/`OPENAI_API_KEY=` assignment, `Authorization: Bearer`, bare `sk-`) with one case-insensitive alternation in a single pass, so an enclosing assignment or header consumes a nested `sk-` key and leaves exactly one marker while keeping the key name or header prefix. The replacement is the fixed `[REDACTED]` with no length or kind hint, secret-free text comes back byte-identical, and nothing may write to a console (the test spies on the sinks).
- `clock.ts` admits one spelling, `YYYY-MM-DDTHH:mm:ss.sssZ`. `format` truncates fractional milliseconds rather than rounding, and `isRecordedAt` round-trips through `Date` so impossible dates are rejected.
- In `wrapper/claims.ts` a claim is a work-item lease, unrelated to the semantic `Claim` in `kernel/identities.ts`, and the file imports nothing from `kernel/`. Liveness comes only from the session record (`isSessionLive`: known, `OPEN`, and `expiresAt` strictly after now). `bootWrapper` never reads `ClaimRecord.expiresAt`, and a live holder's record must stay identical, version included. `version` bumps on every claim and every release, so a takeover of a dead holder bumps it twice and appends a `HOLDER_SESSION_NOT_LIVE` release. Every mutation goes through `backend.write`, which is how the tests model a restart over the same backend.

## Adding or changing a slice

1. Put the module in `kernel/<name>.ts` with a sibling `<name>.test.ts`, and open it with the header comment the other modules use: the PRD sections (or FR ids) it implements and the rules that govern it (`clock.ts` and `redaction.ts` number them).
2. Write imports with double quotes like the other kernel modules. Reuse `uuidV7`/`SurrogateId`, `recordedAt`/`Clock` and `redactSecrets` instead of reimplementing them.
3. Expose a `create*`/`open*` factory that returns frozen values, pass time and hooks in as parameters, and declare closed vocabularies as `as const` arrays with a derived union type (`MODALITIES`, `SENSITIVITY_LEVELS`, `RELEASE_REASONS`).
4. Refuse bad input loudly instead of coercing it: `TypeError` for a wrong type, `RangeError` for an out-of-range value, with the public function name at the start of the message (`captureNote: ...`, `recordedAt: ...`). Conflicts that a caller branches on carry a stable `code` (`ClaimConflictError.code` is `WORK_ITEM_HELD_BY_LIVE_SESSION`).
5. Run the folder's tests (below) and `pnpm typecheck`.

## Running the tests

`pnpm exec vitest run src/kernel src/wrapper src/architecture.test.ts` runs the eight pure suites from the repo root and needs no database or storage. Vitest filters are substring matches, so `vitest run src` or `vitest run src/index.test.ts` also selects `packages/*/src/...` suites that fail without the PostgreSQL harness.

## Traps

- `architecture.test.ts` lives here but guards `packages/domain/src`, which it resolves relative to the current directory. A failure after a domain edit is fixed in `packages/domain`, not by loosening the test.
- Time handling is not uniform. `evidence.ts` stamps `observedAt` and `createdAt` with `new Date().toISOString()` and takes no clock, `claims.ts` takes `clock?: () => Date`, and only `provenance.ts` accepts the kernel `Clock`. `createClock` therefore does not control evidence timestamps in a test.
- The module-level `captureNote`/`listNotes` share one process-wide store, so tests call `resetNotes()` in `beforeEach` or use `createNoteStore()`. `NoteId` is a plain `string`, not a `SurrogateId` brand.
- Section numbers in older header comments are stale: `identities.ts` cites PRD sections 3, 4 and 7 for the identity rule, the identity levels and modality, but in the current `PRD.md` those are §13.1/13.2, §11.4 onward and §11.7 (§3 is about users). Check the heading in `PRD.md` before citing a section in a new header.
- Many test and describe names begin with a `crit-<slug>` id naming the criterion they prove (for example `crit-ingest-persists-before-extraction`); keep those ids when restructuring a suite.
