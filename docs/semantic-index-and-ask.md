## Design entities implemented here

**`memory_embeddings`**, added by `migrations/0019_semantic_index.sql` with forced
RLS, an owner-bound read policy that applies the evidence gate to every read
purpose, an insert policy for the governed write purpose only, composite owner
foreign keys to `claims` and `propositions`, and an immutability trigger. Beside
the design's fields (object reference, owner scope, embedding model and version,
vector, security scope, content hash) it carries the hard-filter columns the
search needs: the evidence items behind the object, their source types and
allowed purposes, the entities of the frame, the object's time span and its
recorded time. There are now 50 application tables, 48 of them owner-scoped and
classified in `packages/postgres/src/ownership.ts`.

The migration adds `unai_private.anchor_evidence_scope` (labels of the evidence
behind anchors, no content, `memory.govern` only) and lets
`unai_private.registry_contract_present` answer under `memory.read`.

No other design entity is implemented here: `answer_manifests` and
`reconsideration_candidates` belong to
`answer-manifests-grounding-validator-and-reconsideration`, and `memory_summaries`
is not needed by any criterion of this node.

## Design screens this node serves

It draws no screen. It drives the design's **Ask** screen through
`POST /v1/ask`, and it supplies the selection reason the **Why? / Sources panel**
and **Answer provenance** will show.

| Ask screen state (design) | What answers it |
| --- | --- |
| Classifying the requested answer type | `answerType` (one of the eight §8.2 types), `queryMode`, `classification.matchedRule` |
| Current-state answer with per-statement certainty labels and source links | `statements[].label`, `statements[].sourceEvidenceIds`, `sourceLinks` |
| Corrected-historical answer | `historicalMode: CORRECTED_HISTORICAL_STATE`, selections at the requested world time with the latest knowledge |
| Historical-belief answer | `historicalMode: HISTORICAL_BELIEF_STATE`, knowledge time pinned to the world time |
| Episode recall, causal explanation, future commitment, prediction review, aggregation answers | the statement set composed for each type |
| Contradiction-check answer presenting both sides | `CONFLICT` statements with every position's value and evidence |
| Answer that includes a pending owner delta and distinguishes it from verification | `OWNER_ASSERTION_PENDING` statements, labelled REPORTED and worded as unverified |
| Unknown or uncertain answer that declines to assert | `UNKNOWN` statements and `declinesToAssert` |
| Refused because the request declared no purpose or an unpermitted purpose | `400 ASK_REQUEST_INCOMPLETE`, `403 CONTEXT_READ_DENIED` |

The states "blocked, downgraded or regenerated by the grounding validator" and
"just-in-time clarification requested" are not produced here; see below.

## How each acceptance criterion is met

- **CRT-RD-03-A** — `selectSlotState` (`packages/context/src/selector.ts`) is a
  pure function applying, in order, the read policy, valid time, knowledge time,
  context and modality, the registry rule, lifecycle, correction and
  supersession, unresolved conflicts and applicable overlay deltas, and records
  per rule what it kept and excluded with a reason code. The broker runs it over
  every slot of every frame in the packet. `packages/context/src/answering.test.ts`
  pins a fixture with a superseded value (a change of due date), a corrected
  value (ILS 50 corrected to 60), a contested value, a pending owner overlay delta,
  a QUOTED-context value and an unregistered-predicate value, runs the broker four
  times — `NOW`/`LATEST` and the same instants pinned — and asserts identical
  selections byte for byte, an identical `selectionsDigest`, the expected outcome
  and reason for every slot, and that no `model_call_records` row was written.
  `question.test.ts` proves the same of the pure function with every input list
  reversed, and the historical selections at a past world and knowledge time.
- **CRT-RD-04-A** — `searchMemoryEmbeddings` (`packages/memory/src/embeddings.ts`)
  runs the owner, permission, sensitivity, knowledge-time, time-window, source and
  entity filters inside a `MATERIALIZED` expression and ranks only what it
  returned. `packages/context/src/semantic.test.ts` gives every excluded object the
  query's own words, proves each is nearer the query than the one admitted object,
  proves none is returned, then lifts each boundary on its own and shows the object
  it excluded coming back first — for sensitivity, purpose, source, time window,
  entity (two people both called Daniel) and knowledge time — and shows another
  owner's identical object is never returned, even when its scope is named. The
  broker's packet carries the same result under the request's own declarations.
  The isolation suite shows the row policy withholds rows from an unfiltered query
  under another purpose or a lower ceiling.
- **CRT-RD-12-A** — `classifyQuestion` (`packages/context/src/question.ts`)
  assigns every fixture question in `question.test.ts` — at least three per type,
  including all of PRD §7.2's Ask examples — to its §8.2 type.
  `answering.test.ts` answers one question per type end to end through
  `answerQuestion` and asserts the type, non-empty source links pointing at the
  fixture's evidence through `/v1/evidence/{id}`, that every statement's links are
  among them, that repeating the question repeats the statements, and the labels:
  CONFIRMED for the corrected value, CONFLICTING for the contested one, COMMITTED
  for the commitment, PREDICTED plus an UNKNOWN "no confirmed outcome" for the
  prediction, REPORTED for the owner's pending delta and for semantic recall.
  `packages/api/src/ask.test.ts` covers the route.
- **CRT-REG-04-A** — `packages/belief/src/unregistered-predicates.test.ts`, over
  the real pinned 0.1.0 release: a claim under `shared.obligation.informal_note`
  commits, is indexed by the commit and is found by semantic search as a
  non-authoritative match; transactions that would use it to supersede an accepted
  belief, resolve a conflict (directly or by lending support), set a current value
  (directly or as the support of a registered value accepted beside it) or
  authorize a high-risk action are each refused with the use named in
  `unregisteredPredicateUses`, and each matching control without the unregistered
  predicate is not refused for that reason. `EvaluateMemoryAction` denies a HIGH
  risk action resting on such memory, and `answering.test.ts` shows the broker
  never selects it and denies the high-risk action founded on a packet holding it.

## Changes to delivered slices

- `@unai/belief`: validation computes the unregistered uses and refuses them; the
  commit indexes every claim it created; `MemoryActionRequest` gains the optional
  `unregisteredPredicateSupport` and the local adapter denies HIGH risk on it.
- `@unai/context` broker: the belief rows read the assessment version live at the
  knowledge time (they read the live row, which answers "now" for any knowledge
  time) and prefer its valid interval to the claims', so a change over time is
  history and not a conflict; selections and the semantic step are added; future
  claims carry their evidence ids.
- `packages/capabilities/src/projection-replay.test.ts` drops and expects
  migration 0019's objects when it re-applies the ledger from 0016, exactly as the
  previous node did for 0017 (and alongside migration 0018's connector objects).

## What this node does not claim

- **No answer manifest, no grounding validator, no model phrasing.** The Ask
  answer is composed by code from the packet; `answer_manifests`, the validator's
  block/downgrade/regenerate actions and reconsideration belong to
  `answer-manifests-grounding-validator-and-reconsideration`. The response carries
  no `answerManifestId` rather than a placeholder.
- **No just-in-time clarification.** An answer blocked by ambiguity is labelled
  UNKNOWN; raising a clarification card belongs to the memory inbox node.
- **Lexical, not neural, semantics.** The pinned embedder matches shared words and
  word fragments, not paraphrase (ADR 0024 §2). Replacing it is a new
  `embedding_version` through the `Embedder` interface.
- **Claims only.** The index covers claims. Raw document text is not indexed here
  (searchable upload is CRT-CON-05-A, the connector node's), and the unattached
  overlay deltas' bounded semantic fallback (`owner_overlay_deltas.embedding_id`)
  is not wired here.
- **Selection covers the frames the packet retrieved.** Frame retrieval is still
  the broker's hint-and-recency retrieval within its frame limit.
- **No deletion of index rows.** The deletion cascade over embeddings belongs to
  `drafts-actions-permissions-export-and-deletion-workflow`; the table grants no
  DELETE today.
